# PaperPilot 文献副驾

国产大模型驱动的 Zotero 7-10 插件：划词翻译 / 精读问答（流式）、工作台 2.0、功能中心、全文对照翻译、AI 综述 / 思维导图 / Anki 制卡、中文元数据、阅读状态、期刊分区与被引量列、界面与 PDF 阅读主题（含动漫配色）、库健康维护……一个插件覆盖文献工作流。

> 当前版本：**0.24.3** ｜ 兼容 Zotero 7 / 8 / 9 / 10

> **0.24.3 修复（真机验证·推荐质量）**：**推荐「零信号」时不再静默**。实测在真实库上（中医 / 抽动障碍主题 + 默认 `cs.AI, cs.CL, cs.LG` 分类）跑完每日定时后，30 条推荐**全都是 9.1 分、没有任何一条与库内兴趣词真实重合**（只命中了分类加成）——即分类与研究领域不匹配时，界面会给出**一张看起来完全正常的无用清单**。现在 `scoreEntry` 会分别统计「画像词元命中数」与「分类加成」，当整批推荐的词元命中数为 0 时，窗口顶部显示橙色告警并给出可执行建议（换成领域对应的分类，如神经科学 `q-bio.NC`；或清空分类框改用库内兴趣词检索），存为笔记时也带上该提示。

> **0.24.2 修复（真机验证·用真实库数据复算发现）**：① **DOI 有效性规则把 shortDOI 全判成非法** —— 原正则要求 `10.` 后跟 4–9 位注册号，而 Crossref 的 shortDOI 形如 `10/gq7zfp`，真实库 1000 条里产生 **71 条误报**；现接受 shortDOI 并把尾段放宽到「无空白即可」（顺带修掉对 Wiley 旧式含 `<>()` 合法 DOI 的误报），误报 71 → 1。② **期刊「尾随句点」规则会破坏缩写刊名** —— 命中的 7 条全是 `Ann. Neurol.` / `J. Child Neurol.` / `Psychiatry Res.` 这类缩写体（末尾句点是缩写规范的一部分）；现新增缩写体识别，只清理「全称末尾多了一个句点」（`Nature.`）。③ **兴趣画像被噪声标签与中文分词双重破坏** —— Better BibTeX 打的 `⛔ No INSPIRE recid found`（176 条）`/unread`（301 条）经标签 ×3 加权后让 `inspire` 成了画像第一词、推荐全被功能词带偏；同时画像选词写了 `长度 ≥ 3`，而**中文词元是 2 字 bigram**，导致「抽动/障碍/中医/中药」这类核心词**一个都进不了画像**。现加标签噪声识别（保留 `《书名》“引号”` 这类内容型标签）、补齐中英文停用词、长度下限改为 ≥2；同一份真实数据上画像从「全英文功能词」变为 `中医/tourette/syndrome/中药/抽动/障碍/tic` 等真实主题词。
>
> **0.24.1 修复（真机验证发现）**：`Zotero.Library` 上**根本没有 `getCollections()` 方法** —— MCP 的 `list_collections` 与 arXiv 日推的「收藏到库（加入分类）」都误用了它，调用抛 `TypeError` 又被 `try/catch` 吞掉：前者对外报告「库中还没有任何分类」这个**看起来合理但完全错误**的答案（实际库里有分类），后者表现为「收藏成功但没进分类」。现统一改用 `Zotero.Collections.getByLibrary(libraryID, recursive, includeTrashed)`，并把「接口失败」与「确实为空」在输出里**明确区分** —— 拿不到数据就报错，绝不伪装成空结果。

> **0.24.0 新增（功能路线图阶段 3 · 补两个空白功能域）**：
> **① 文献发现（arXiv 每日推荐）**——PaperPilot 过去只回答「你已经知道要读什么」，这版补上反向能力：先用库里已有文献建**兴趣画像**（标题 ×3 / 标签 ×3 / 期刊 ×2 / 摘要 ×1 加权的词元频次，并剔除在过多条目里出现的泛词；同时从 extra / url / archiveID 抽出 arXiv 分类作为偏好），再按分类（未填分类时改用画像词元）拉取 arXiv 最新提交，按「标题命中 ×3 ＋ 摘要命中 ×1 ＋ 分类加成 ＋ 新近度」打分排序；**已在库里的（按 arXiv id / DOI / 归一化标题）与已被忽略的自动排除**。结果按天缓存，打开窗口不重复请求；每条可「打开 / 看 PDF / 收藏到库（自动建「arXiv 推荐」分类）/ 忽略」，整批可「存为笔记」，并支持每日自动刷新（默认关）。
> **② MCP 对外供给**——把「库检索 / 读全文 / 读批注 / 写笔记 / 取元数据 / 分类列表 / 库统计 / 最近入库」8 项能力封装为 **MCP 工具**，供 Claude Desktop、Cursor 或自建 Agent 直接调用。载体是 Zotero 自带的本地 HTTP 服务（默认 `127.0.0.1:23119`，**零额外依赖**），实现 JSON-RPC 2.0 与 MCP Streamable HTTP 的「单次 JSON 响应」形态。**三重安全**：只监听回环地址、每个请求都要 Bearer 令牌（首次自动生成、可重置）、**默认不启用**；窗口会显示 Zotero 本地服务运行状态（端点由它承载，被关掉时端点不会被监听）并提供一键恢复。含端到端自检与可复制的客户端配置 JSON。
> **③ 元数据体检（规则补齐）**——在「元数据规范清洗」（只做格式规范化、命中即修）之上补一层**语义体检 + 勾选修复**：期刊缩写 ↔ 全称互转（内置 100 条常用刊表 + 设置里可自定义，默认把缩写展开为全称，方向可改或关闭）、作者名归一化（单栏姓名拆分 / `Last, First` 逗号逆序 / 全角空格与多余空白 / 尾随句点，且不误伤 `Jr.`）、DOI 有效性体检（含前缀、含空格、语法不符）、条目类型必备字段缺失（如期刊论文缺期刊名）、以及**扫描范围内的重复 DOI**。纪律与标签治理一致：先出问题清单 → 用户勾选 → 才写库；提示类只展示不自动修改。
> **0.23.0 新增（双线合并发版）**：**① 账号与会员（服务端 1.4.0）**——根治「每次更新 xpi 后登录信息丢失」：真凶是 `IOUtils.writeUTF8(p, t, { mode: 0o600 })` ——`options.mode` 要的是**字符串枚举**（`"append"` / `"create"` / `"overwrite"`），传数字 `0o600` 等于这次写入**不产出任何文件**，而紧随其后的 `catch` 只把错误打进调试控制台，于是「✓ 登录成功」的提示与磁盘上的空文件长期共存（前三次修复都没定位到这里）。现改为**多代冗余会话仓库**：2 个落点 × 3 代滚动副本 = 最多 6 份，按 `savedAt` 取最新有效者；写入带硬超时与回读校验、失败自动回退；登出 / 服务端确认失效时用**墓碑覆盖全部代际**，防止旧副本把已登出的会话「复活」。同时新增**会员体系**（套餐与权益、价格档、订单、激活码兑换、收款码，全部后台可改），设置面板新增会员卡片。**② 功能路线图阶段 2**：**自动化引擎**——把原来只能打标签的「规则打标」升级为通用的「触发 → 条件 → 动作」自动化：触发可选「新条目入库 / 打开 PDF / 手动对选中条目」；条件支持 17 个字段 × 9 种操作（含正则，默认忽略大小写），多条件可「全部满足 / 任一满足」；动作支持打标签、去标签、写字段（白名单字段，防误改标题/DOI）、设阅读状态、加入分类、AI 总结生成笔记、AI 自动打标签。配套可视化规则编辑器（左列规则、右侧表单、启用勾选）、**试跑预览**（只统计命中与变更数、不落库）、内置 4 条示例、一键导入旧「规则打标」规则，以及批量配额与 AI 每日额度闸门。**入库自动精读**——新条目入库后自动生成总结笔记并打上 `#AI精读`：默认关闭、可限定分类白名单、每日上限（默认 10 篇）、已有精读产物不重复处理。两个入口都在 **工具 → PaperPilot 自动化规则**（开关也在这一个窗口里）。

## 安装

1. 到 [Releases](../../releases) 下载最新 `paper-pilot-x.y.z.xpi`
2. Zotero → 工具 → 插件 → 右上角齿轮 → **Install Plugin From File**，选择 xpi
3. 重启 Zotero，打开 **编辑 → 设置 → PaperPilot** 填写 API Key

## AI 配置（0.14.0：账号 + 模型通道）

**方式一：登录账号（推荐，零配置）**——设置 → PaperPilot 登录后即可**免费使用官方默认模型**（连接官方服务器 `https://pp.xinglintools.top`，没有账号点「注册账号」自助注册）；账号卡片可查看套餐与每日用量、切换官方模型，登录状态本地持久化，过期自动提醒。官方服务由 PaperPilot 统一提供，不开放自建后台。

**方式二：自己的接口**——「AI 模型通道」支持注册多套 OpenAI 兼容配置（`/v1/chat/completions`）：

- 17 家厂商预设（DeepSeek / 通义 / Kimi / 智谱 / 豆包 / 硅基流动 / Ollama 本地……），粘贴 API Key 点「🔍 检测」自动识别厂商并拉取模型
- 通道可新增 / 编辑（Key 留空保持不变）/ 删除 / **实测**（真实调用返回延迟与应答）/ 一键切换；extraBody 附加参数、超时、模型列表 chips 管理
- 工具菜单与工作台内均可快速切换活动通道；旧版单通道配置与快照首次启动自动迁移为通道

设置中不预置任何密钥——请登录账号或填自己的 Key。

## 账号后台与启动管理器（0.14.0，0.14.1 增强）

仓库自带一套零依赖 Node 账号后台（`server/`），实现插件全部账号契约：注册/登录/会话/用量 + 官方模型网关（把登录用户请求转发到活动通道上游，`auto` 模型自动映射、SSE 流式透传）。

**双击项目根目录 `启动PaperPilot后台.bat`** 打开图形控制台（WinForms，对标心血管药物学习平台启动管理器）：

- **账号后台控制**：启动 / 停止 / 重启 / 查看日志 + 状态灯（端口 8000 健康检测）；可设开机自启
- **AI 模型通道管理**：通道列表 / 新增 / 编辑 / 删除 / 设为活动 / 实测 / 🔍 按密钥检测厂商 / 📡 拉取上游模型（17 家预设联动填充）——决定官方网关走哪个上游
- **官方默认模型（0.14.1）**：通道管理里一行搞定——📡 拉取活动通道模型列表 → 下拉选择（或输入自定义名）→ 设为默认，登录用户的 `auto` 即时走此模型；插件设置中的模型 chips 同样点击即选
- **账号管理**：注册账号 / 用户列表 / 改套餐与有效期 / 重置密码（吊销全部会话）/ 删除
- 关闭窗口 = 最小化到托盘驻留；也可在浏览器打开 `http://127.0.0.1:8000/admin` 网页版管理
- **公网部署（多设备/公开服务）**：经 Cloudflare Tunnel 接入自有域名（现网 `https://pp.xinglintools.top`），任何人可自助注册登录；管理面仍仅限服务器本机。步骤见 `docs/账号系统与模型通道.md`

首次使用：启动后台 → 通道管理新增一条上游并设为活动 → 注册账号 → Zotero 设置里登录即可。详见 `docs/账号系统与模型通道.md`。

## 更新通道

插件内置 `update_url`（0.14.4 起 = Gitee raw 直链），新版 push 后 Zotero 自动提示更新（无需手动重装，`git push origin main` 即发版）。
更新清单：`paperpilot-update.json`（版本条目 + Gitee raw xpi 直链）。
> 0.14.3 及更早版本的 `update_url` 指向 gujinbencao 服务器——存量用户需将仓库 `paperpilot-update.json` 上传一次到该服务器对应路径，即可收到 0.14.4 并永久切换到 Gitee 链路。

## 版本迭代流程

1. 改代码 → `manifest.json` 版本号 +1
2. 打包：`python` 把 `paper-pilot/` 打成 `paper-pilot-<版本>.xpi`（zip，源码目录内容置于根）
3. `paperpilot-update.json` 追加新版本条目
4. 提交并打 tag：`git tag v<版本> && git push origin master --tags`
5. GitHub/Gitee Releases 上传 xpi 附件

## 隐私

- 登录令牌保存在本机 Zotero 数据目录（`paperpilot-account.json`，仅本地读写），密码只在登录请求中出现、绝不落盘；卸载插件即清除
- 所有 AI 请求只发往你登录的官方网关或自己配置的服务商/本地网关，插件无任何遥测与回传
- 「真假文献识别」「被引量」等只访问 Semantic Scholar / easyScholar / Unpaywall 公开 API；「补全文」在启用补充渠道时（默认开启，可在设置中关闭）还会访问 Sci-Hub / Sci-Net（仅供个人学术研究）
